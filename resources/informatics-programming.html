共通考试里算法题怎么考

大学入試センター的问题作成方针说明，程序题会使用考生初见也能理解的独自程序表记。 所以重点不是背语法，而是把题目中的处理过程翻译成“变量怎样变、条件何时成立、循环执行几次”。

做题顺序：确认输入输出 → 标出变量初始值 → 逐行执行 → 写追踪表 → 检查最后输出。

本页覆盖的核心能力

  • 二进制、位、字节和数据量计算。
  • 读懂赋值、条件分支、循环和数组。
  • 追踪线性搜索、最大值查找、相邻交换排序。
  • 比较算法效率，理解数据量变大后的影响。
  • 用简单规则建立模型并进行模拟。

01 二进制与位

计算机内部用 0 和 1 表示信息。一个二进制位叫 bit，8 bit 通常称为 1 byte。

重要结论：从右往左，第 k 位的权重是 2^k。8 bit 无符号整数的范围是 0 到 255。

173 = 10101101₂

典型题的看法

  1. 先写出位权：128, 64, 32, 16, 8, 4, 2, 1。
  2. 从最大的位权开始，能减就写 1，不能减就写 0。
  3. 数据量换算时注意 1 byte = 8 bit。

常见错误：把 1000₂ 看成一千；把 bit 和 byte 混用；忘记最高位权重随位数改变。

02 变量追踪

赋值符号「←」表示把右边的计算结果放进左边变量。变量被重新赋值后，旧值会被覆盖。

合計 ← 0
i を 1 から n まで 1 ずつ増やす:
  合計 ← 合計 + i
表示する(合計)
n = 6
回数i合計

追踪表怎么写

  1. 每个变量单独开一列。
  2. 循环每执行一次，就追加一行。
  3. 如果输出在循环外，最后一行才是答案。
  4. 如果输出在循环内，要看第几次输出。

考试意识：程序题常用“第几次循环后”“当 i = ? 时”来考边界条件。

03 条件分支与循环

条件分支决定“走哪条路”，循环决定“重复几次”。算法题最容易错在边界：等号有没有包含、循环什么时候结束。

もし x が 2 で割り切れる ならば:

  表示する("奇数")
14 是偶数

分支题的检查点

  • < 和 ≤ 的差别。
  • 多个条件同时出现时，是“且”还是“或”。
  • 循环变量是否在循环内更新。
  • 循环结束后变量已经变成什么。

04 数组与下标

数组把多个数据按顺序放在一起。共通考试题会在题干说明下标从 0 还是从 1 开始，一定要先确认。

最大 ← 点数[1]
i を 2 から データ数 まで 1 ずつ増やす:
  もし 点数[i] > 最大 ならば:
    最大 ← 点数[i]
准备开始

数组题的核心

  1. 确认数组长度和下标起点。
  2. 确认循环从第几个元素开始。
  3. 更新最大值、最小值、合计时，记录旧值和新值。
  4. 不要把“第 i 个”与“下标 i”混在一起。

05 线性搜索

线性搜索从头到尾逐个比较，直到找到目标，或确认没有目标。数据没有排序时，这是一种最直观的查找方法。

見つかった ← 偽
i を 1 から データ数 まで 1 ずつ増やす:
  もし データ[i] = 目標 ならば:
    見つかった ← 真
目标 68

命中与未命中

  • 最好情况：第一个元素就是目标，只比较 1 次。
  • 最坏情况：目标在最后，或根本不存在，要比较 n 次。
  • 如果数据已经排序，可以使用二分搜索；如果未排序，不能直接二分。

06 排序：相邻比较与交换

排序是把数据按规则排成顺序。这里用相邻比较演示：如果左边比右边大，就交换。重复进行后，大的数会逐步移到右侧。

准备开始

观察点：一次 pass 结束后，当前未排序部分的最大值会确定在右端。数据量增加时，比较次数会明显增加。

07 算法效率

算法效率关注数据量 n 变大时，处理次数怎样增长。共通考试不要求严格证明，但要能比较“哪个增长更快”。

n = 20

常见增长方式

常数时间

O(1)
取数组第 3 个元素。

线性时间

O(n)
逐个检查所有元素。

平方时间

O(n²)
两层循环比较所有组合。

考试意识：数据量变成 2 倍时，O(n) 约变 2 倍，O(n²) 约变 4 倍。

08 模型化与模拟

现实问题太复杂时，可以用变量和规则建立模型，再让程序重复计算。模拟结果不是绝对真实，而是“在这些假设下会怎样”。

  • 先明确假设：忽略什么、保留什么。
  • 决定每一步如何更新状态。
  • 结果是否受初始值、随机数或参数影响。
